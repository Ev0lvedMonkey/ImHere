# Прототип виджета — инструкция по проверке

Ветка: `feature/widget-prototype`
Версия: `0.1.0-prototype`

## Что уже реализовано

- SOS-виджет (`AppWidgetProvider` + `RemoteViews`) с состояниями «Двойное нажатие» → «Нажмите ещё раз» → «Выполняется…».
- Двойное нажатие с окном 2 секунды (монотонное время, состояние переживает смерть процесса).
- Запуск `ForegroundService` с типом `location` из виджета, без открытия Activity.
- Получение геолокации: Fused Location Provider, при отсутствии Google Play Services — `LocationManager`.
- Таймаут 20 секунд, проверка возраста (≤ 30 с) и точности (≤ 100 м).
- Уведомления о ходе и результате операции.
- Экран прототипа: выдача разрешений, статус, запуск пайплайна без виджета, диагностический режим.

SMS в прототипе **не отправляются** — это следующий этап.

## Установка

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

## Первый запуск

1. Откройте приложение ImHere.
2. Нажмите «Выдать разрешения» и разрешите геолокацию (желательно «Точное местоположение») и уведомления.
3. Убедитесь, что в статусе: геолокация — «выдано», уведомления — «выдано», службы геолокации — «включены».

## Добавление виджета

Долгое нажатие на пустом месте рабочего стола → «Виджеты» → ImHere → перетащите виджет SOS на экран.

## Сценарии проверки

Отмечайте результат каждого пункта: OK / FAIL + версия Android, модель, прошивка.

| № | Сценарий | Ожидание |
|---|---|---|
| 1 | Одно нажатие | Виджет оранжевый, «Нажмите ещё раз», SMS/геолокация не запускаются |
| 2 | Второе нажатие через ~1 с | Виджет серый «Выполняется…», появляется уведомление «Получение геолокации…», затем результат |
| 3 | Второе нажатие через 2.5 с | Новый цикл: виджет снова оранжевый «Нажмите ещё раз», SOS не запускается |
| 4 | Повторные нажатия во время операции | Операция не запускается повторно, виджет остаётся «Выполняется…» |
| 5 | Экран заблокирован → разблокирован, затем двойное нажатие | SOS запускается |
| 6 | Приложение закрыто (свайп из недавних), двойное нажатие | SOS запускается, Activity не открывается |
| 7 | `adb shell am force-stop com.imhere.app`, затем нажатие на виджет | Ожидаемое ограничение: Android не доставляет виджет-события остановленному приложению. Зафиксировать фактическое поведение |
| 8 | Перезагрузка телефона, затем двойное нажатие | SOS запускается (если в MIUI разрешён автозапуск приложения) |
| 9 | Геолокация выключена, двойное нажатие | Уведомление «Службы геолокации отключены», SMS нет |
| 10 | Разрешение на геолокацию отозвано, двойное нажатие | Уведомление «Нет разрешения на геолокацию» |
| 11 | Запуск из приложения кнопкой «Запустить SOS-пайплайн без виджета» | Тот же результат, что и из виджета |
| 12 | Точность хуже 100 м (например, в помещении) | Ошибка «Недостаточная точность»; для проверки механики включите «Режим прототипа: принимать неточную геолокацию» |

## Логи

```powershell
adb logcat -s ImHerePrototype
```

Ключевые строки: `widget tap`, `first tap`, `second tap confirmed`, `onStartCommand`, `resolve:`, `SOS location success/failure`, `SOS operation finished`.

## Известные ограничения прототипа

- Визуальный сброс «Нажмите ещё раз» делается через `Handler`; если процесс убит сразу после первого нажатия, виджет может остаться оранжевым до следующего нажатия. Функционально это безопасно: устаревшая метка не считается вторым нажатием.
- На некоторых прошивках (MIUI) фоновая работа ограничена: нужен автозапуск и отключение агрессивного энергосбережения для ImHere.
- Если уведомления запрещены, результат операции виден только в Logcat.
- Проверка на Android 14+ (ограничения while-in-use) требует отдельного устройства.
