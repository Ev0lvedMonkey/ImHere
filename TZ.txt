# Техническое задание: Android-приложение для быстрой передачи геолокации (SOS)

## Роль и задача

Ты — опытный Android-разработчик и архитектор программного обеспечения. Твоя задача — спроектировать и реализовать полноценное Android-приложение для быстрой передачи текущего местоположения выбранным контактам посредством SMS.

Не ограничивайся демонстрационным прототипом. Результат должен быть пригоден для тестирования на реальных Android-устройствах и распространения в виде APK через GitHub Releases.

Главный приоритет — надёжность, скорость и простота выполнения SOS-сценария. Пользователь должен иметь возможность отправить сигнал помощи практически мгновенно, не открывая основной интерфейс приложения.

---

# 1. Концепция приложения

Приложение позволяет пользователю быстро отправлять своё текущее местоположение заранее выбранным контактам.

Основной сценарий — экстренная отправка SMS с координатами пользователя.

Приложение также должно поддерживать обычную однократную отправку геолокации без экстренного сценария.

Основные принципы:

- Минимальное количество действий пользователя.
- Максимальная надёжность получения геолокации.
- Прямая отправка SMS без открытия стороннего SMS-приложения.
- Возможность запуска SOS через виджет Android.
- Работа без подключения к интернету, если доступны необходимые источники геолокации и мобильная сеть.
- Локальное хранение всех пользовательских данных.
- Отсутствие регистрации, серверов и синхронизации.

Приложение не является заменой официальным экстренным службам.

# 3. Основные сценарии использования

## 3.1. SOS через приложение

Последовательность действий:

1. Пользователь открывает приложение.
2. Нажимает большую кнопку SOS.
3. Приложение проверяет наличие необходимых разрешений и доступность выбранной SIM.
4. Запускается получение актуальной геолокации.
5. Приложение проверяет возраст и точность координат.
6. Формируется сообщение на основе пользовательского шаблона.
7. Сообщение отдельно отправляется каждому выбранному SOS-контакту.
8. Приложение получает статусы отправки SMS.
9. Пользователь видит результат операции по каждому получателю.

Если получение подходящей геолокации невозможно, SMS не отправляется.

Если отправка одному получателю завершилась ошибкой, приложение продолжает отправку остальным.

## 3.2. SOS через виджет Android

Это один из важнейших сценариев приложения.

### Основная задача

Пользователь должен иметь возможность:

1. Разблокировать телефон.
2. Нажать на SOS-виджет.
3. Повторно нажать на него в течение 2 секунд.
4. Дождаться получения геолокации.
5. Автоматически отправить SMS заранее выбранным контактам.

Пользователю не требуется открывать основной интерфейс приложения или SMS-приложение.

### Требования к виджету

- Виджет должен содержать кнопку SOS.
- Первое нажатие переводит виджет в состояние ожидания второго нажатия.
- Второе нажатие в течение 2 секунд запускает SOS.
- Если интервал превышен, следующее нажатие начинает новый цикл.
- Визуально показывать состояние ожидания второго нажатия.
- После запуска SOS блокировать повторный запуск до завершения текущей операции.
- После завершения операции возвращать виджет в исходное состояние.
- При ошибке показывать соответствующее уведомление.

### Техническая реализация

Не пытайся выполнять получение геолокации и отправку SMS непосредственно внутри BroadcastReceiver.

Предусмотри отдельный механизм выполнения SOS, например:

- AppWidgetProvider принимает нажатие.
- Проверяется интервал между нажатиями.
- При подтверждённом двойном нажатии запускается необходимый компонент приложения.
- Для длительной операции используется подходящий механизм фонового выполнения, при необходимости Foreground Service с типом location.
- Основной интерфейс приложения не открывается.
- Пользователь получает уведомления о ходе и результате операции.

Учитывай ограничения Android на запуск фоновых сервисов, доступ к геолокации и выполнение операций после блокировки экрана.

**Обязательное условие:** сначала создай и проверь технический прототип двойного нажатия и запуска SOS через виджет. Не переходи к полной реализации виджета, пока не подтверждена работоспособность подхода на реальном устройстве.

Если на определённых версиях Android или устройствах невозможно обеспечить выполнение без открытия Activity, не скрывай ограничение. Предложи минимально заметный совместимый вариант и объясни его необходимость.

Не запрашивай разрешение на фоновую геолокацию без доказанной необходимости.

## 3.3. Обычная отправка геолокации

Пользователь может отправить своё местоположение без использования SOS.

Требования:

- Кнопка «Отправить геолокацию».
- Возможность выбрать одного или нескольких сохранённых контактов.
- Получение актуальных координат.
- Проверка точности и возраста координат.
- Формирование обычного сообщения.
- Отправка отдельного SMS каждому выбранному получателю.
- Отображение результата отправки.

Для обычной отправки используется тот же механизм получения координат и отправки SMS, что и для SOS.

# 4. Работа с контактами

Пользователь должен иметь возможность:

- Добавлять контакты вручную.
- Выбирать контакты из телефонной книги через системный интерфейс Android.
- Редактировать контакты.
- Удалять контакты.
- Выбирать несколько получателей.
- Отмечать контакты, используемые для SOS.

### Требования к контактам

Каждый контакт содержит:

- Имя.
- Один основной номер телефона.
- Признак использования в SOS.

Для первой версии достаточно одного номера на контакт.

Предусмотреть:

- Проверку корректности номера.
- Хранение номера в международном формате.
- Защиту от дублирования одинаковых номеров.
- Подтверждение удаления контакта.
- Автоматическое исключение удалённого контакта из SOS-получателей.

Не запрашивай разрешение READ_CONTACTS, если выбор контакта можно реализовать через системный интерфейс Android.

Контакты должны сохраняться между перезапусками и обновлениями приложения.

Предусмотреть:

- Корректную обработку отсутствующих данных.
- Значения по умолчанию.
- Проверку целостности данных.
- Обработку ошибок сериализации.
- Безопасное обновление структуры данных при изменении модели приложения.
- Сохранение настроек после перезапуска устройства.

### 6.3. SIM-карта

Требования:

- Если установлена одна активная SIM, использовать её автоматически.
- Если установлено несколько SIM, предоставить возможность выбора.
- Сохранять выбранную SIM между запусками.
- При запуске SOS проверять доступность выбранной SIM.
- Если выбранная SIM отсутствует или недоступна, отменять отправку и уведомлять пользователя.
- Не переключаться автоматически на другую SIM.
- Если SIM заменена или её идентификатор изменился, предложить пользователю выбрать доступную SIM заново.

Для определения доступных SIM использовать соответствующие Android API, включая SubscriptionManager там, где это необходимо.

Учитывать ограничения доступа к информации о SIM на разных версиях Android.

# 8. Геолокация

## 8.1. Источники координат

Использовать Fused Location Provider API, если доступны Google Play Services.

Предусмотреть резервную реализацию через Android LocationManager для устройств без Google Play Services.

Не ограничивать получение местоположения исключительно GPS.

Использовать доступные источники местоположения Android.

## 8.2. Требования к актуальности

При каждом запуске SOS приложение должно запрашивать новое местоположение.

Установить следующие параметры:

| Параметр | Требование |
|---|---|
| Максимальное ожидание новой геолокации | 20 секунд |
| Допустимый возраст последней известной позиции | Не более 30 секунд на момент отправки |
| Максимальная допустимая погрешность | 100 метров |
| Минимальная точность | `accuracy <= 100 m` |

Если новая геолокация получена за время ожидания, использовать её при соблюдении требований к точности.

Если новую геолокацию получить не удалось, допускается использование последней известной позиции, если одновременно выполняются условия:

- Возраст позиции на момент отправки не превышает 30 секунд.
- Точность не хуже 100 метров.

Если ни одна позиция не соответствует требованиям, SMS не отправляется.

Не использовать координаты с неизвестной точностью.

Не выдавать устаревшую позицию за актуальную.

## 8.3. Обработка ошибок

Предусмотреть:

- Отключённые службы геолокации.
- Отсутствие разрешения на геолокацию.
- Отказ пользователя в доступе к точной геолокации.
- Невозможность получения координат.
- Превышение таймаута.
- Недостаточную точность.
- Отсутствие Google Play Services.
- Отсутствие интернета.

При невозможности получить подходящую геолокацию отправка SMS отменяется.

Если пользователь отказал в разрешении на точную геолокацию, объяснить причину и предложить изменить разрешение.

## 8.4. Текстовый адрес

Использовать Android Geocoder или другой подходящий бесплатный механизм.

Определение адреса необязательно.

Требования:

- Не задерживать отправку SMS ради определения адреса.
- Не зависеть от наличия интернета.
- Если адрес получить невозможно, продолжить формирование сообщения без него.
- Координаты и ссылка на карту должны формироваться независимо от адреса.

## 8.5. Ссылка на карту

Использовать следующий формат:

`https://www.google.com/maps/search/?api=1&query={latitude},{longitude}`

Ссылка должна открываться в браузере или совместимом картографическом приложении.

Не требуется наличие установленного Google Maps.

# 9. Отправка SMS

Основной и единственный канал передачи сообщений — SMS.

Не реализовывать Telegram, WhatsApp и другие мессенджеры.

## 9.1. Механизм отправки

Использовать Android SmsManager.

Не открывать системное SMS-приложение.

Не требовать подтверждения отправки каждого сообщения через сторонний интерфейс.

Пользователь должен один раз предоставить необходимые разрешения, после чего отправка должна происходить непосредственно через Android API.

## 9.2. Разрешения

Предусмотреть необходимые разрешения:

- `SEND_SMS`.
- `ACCESS_FINE_LOCATION`.
- `ACCESS_COARSE_LOCATION`.
- Другие разрешения только при доказанной необходимости.

Для работы Foreground Service и виджета учитывать дополнительные разрешения и ограничения соответствующих версий Android.

Запрашивать разрешения непосредственно перед использованием соответствующей функции.

Объяснять пользователю назначение чувствительных разрешений.

Не запрашивать `READ_CONTACTS`, если используется системный интерфейс выбора контактов.

Не запрашивать `ACCESS_BACKGROUND_LOCATION` без доказанной необходимости.

## 9.3. Несколько получателей

Для каждого получателя отправлять отдельное SMS.

Не использовать групповую рассылку одним сообщением.

Логика:

1. Проверить список получателей.
2. Проверить корректность номеров.
3. Проверить выбранную SIM.
4. Сформировать сообщение.
5. Начать отправку отдельного SMS каждому контакту.
6. Отслеживать результат каждого сообщения.
7. При ошибке одного получателя продолжить отправку остальным.

## 9.4. SIM-карта

Использовать выбранную пользователем SIM.

Если выбранная SIM недоступна, отправку не выполнять.

Не использовать другую SIM автоматически.

## 9.5. Статусы отправки

Использовать соответствующие PendingIntent и BroadcastReceiver для получения результатов отправки.

Разделять следующие состояния:

- Ожидает отправки.
- Отправлено оператору.
- Ошибка отправки.
- Ожидается подтверждение доставки.
- Доставлено.
- Не доставлено, если оператор предоставил соответствующий статус.

Не считать открытие SMS-сервиса или вызов SmsManager подтверждением успешной отправки.

Не утверждать, что SMS доставлено, если получен только статус успешной передачи оператору.

Учитывать, что отчёты о доставке зависят от оператора и устройства и не всегда доступны.

## 9.6. Длинные сообщения

Предусмотреть корректную обработку сообщений, превышающих один SMS-сегмент.

Использовать multipart SMS при необходимости.

Корректно обрабатывать ошибки отправки отдельных частей сообщения.

# 10. Обработка ошибок и надёжность

Приложение должно корректно обрабатывать следующие ситуации:

- GPS или службы геолокации отключены.
- Нет разрешения на геолокацию.
- Нет разрешения на SMS.
- Не удалось получить координаты.
- Недостаточная точность координат.
- Истекло время ожидания.
- Нет SIM-карты.
- Выбранная SIM недоступна.

# 14. Критерии приёмки

Приложение считается реализованным, если выполняются следующие условия:

### Основной SOS-сценарий

- Пользователь может настроить контакты и SOS-получателей.
- Пользователь может выбрать SIM-карту.
- Пользователь может изменить шаблон сообщения.
- При нажатии SOS приложение получает подходящую геолокацию.
- Формируется корректное сообщение с координатами и ссылкой на карту.
- SMS отправляется каждому получателю отдельно.
- Ошибка одного получателя не прерывает отправку остальным.
- Результат отправки отображается отдельно для каждого контакта.

### SOS через виджет

- Виджет добавляется на домашний экран.
- Первое нажатие активирует ожидание второго.
- Второе нажатие в течение 2 секунд запускает SOS.
- Основной интерфейс приложения не открывается.
- При успешном получении координат SMS отправляются автоматически.
- При невозможности получить подходящие координаты SMS не отправляются.
- Пользователь получает уведомление о результате.

### Обычная отправка

- Пользователь может выбрать контакты.
- Геолокация получается по тем же правилам, что и в SOS.
- SMS отправляется выбранным контактам.
- Результат отображается пользователю.

### Локальные данные

- Контакты сохраняются.
- Настройки сохраняются.
- Выбранная SIM сохраняется.
- История геолокаций и SOS отсутствует.

### Качество

- Проект собирается без ошибок.
- Нет заведомо устаревших или несуществующих API.
- Нет критических ошибок при работе с разрешениями.
- Основные сценарии проверены на реальном устройстве.
- Подготовлена релизная APK-сборка.
